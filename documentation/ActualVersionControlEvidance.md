### Development workflow

Further improvements are developed on separate
branches instead of modifying the main branch
directly.

Before merging an improvement:

1. Review the modified files.
2. Run the automated tests.
3. Push the feature branch to GitHub.
4. Create a pull request.
5. Review the changes and test results.
6. Merge the approved change into main.

### Why this approach is useful

Branching allows individual improvements to be
developed without immediately changing the stable
version of the application.

Small commits make code changes easier to understand,
review, debug, and revert.

Pull requests provide an opportunity to review changes
before integrating them into the main branch.

This process supports maintainability and reduces the
risk of introducing untested changes.
